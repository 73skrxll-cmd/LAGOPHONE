# Блокировки — GTM PC 0.21.2

Раздел содержит два отдельных механизма: **DiscordFix** на базе Zapret 1.10.4 для сервисов и **FortniteFix** на базе адаптированного headless-ядра fnport 0.6.3. Это работающие локальные сетевые компоненты, а не VPN, удалённый узел или обещание снижения пинга. Возможность обхода зависит от провайдера и вида ограничения.

«Блокировки» находятся сразу под «Твиками» в боковом меню. Та же анимация заполнения и свечения использует отдельную сине-бирюзовую палитру; общая настройка анимаций управляет обоими пунктами.

## Как пользоваться (0.21.2)

Обе карточки показывают крупные плашки «ВКЛЮЧЕНО / ВЫКЛЮЧЕНО» с переливом. Во время поиска DiscordFix показывает «ПОДБОР», поскольку временный запуск тестовой стратегии не означает, что выбран пользовательский режим. Анимации подчиняются общим настройкам и prefers-reduced-motion.

1. Отключите сторонний VPN, закройте игры и отключите FortniteFix перед поиском.
2. В видимом блоке «Найдём вашу стратегию» нажмите «Найти стратегию». Подтвердите штатный запрос Windows для сетевого супервизора.
3. Дождитесь перебора всех 22 стратегий. Прогресс показывает текущий вариант и выполненные этапы. Поиск можно остановить, прежний режим будет восстановлен.
4. Выберите результат или вариант из списка и нажмите «Включить выбранную». Рекомендуемый вариант уже выделен. Выбор сохраняется для следующего запуска GTM PC.
5. Проверьте голос/видео Discord или YouTube. Кнопка в карточке отключает работающий фикс. «Что проверялось» содержит адреса, методику и сохранение отчёта.

FortniteFix использует отдельный алгоритм подбора портов. Закройте игру, отключите VPN/WARP/GearUP, включите FortniteFix, затем запустите Fortnite через Epic. Не включайте VPN во время матча: смена маршрута может оборвать соединение. Игра должна быть закрыта при изменении сетевого режима; чужие VPN приложение не отключает.

## Подбор стратегии из архива

Изучена `utils/test zapret.ps1` из официального архива Flowseal 1.10.4, совпадающего с архивом пользователя. Её основной принцип — запускать каждую исходную стратегию, проверять соединения разными версиями TLS и сравнивать успешные ответы. В GTM PC эта методика адаптирована для интерфейса: терминал и отдельное окно не открываются, BAT-меню и исходная команда остановки всех winws не выполняются.

Каждая стратегия проверяется на одинаковых фиксированных HTTPS IPv4 целях: API/CDN Discord, страница и изображение YouTube. Для каждой цели открываются новые TLS 1.2 и TLS 1.3 соединения; выполняются две серии, всего 16 запросов на стратегию. Проверяются сертификат, HTTP-код и фактическое получение данных. Для страницы YouTube требуется не менее 32 КиБ, чтобы короткий ответ сам по себе не считался успешной загрузкой. Ошибки TLS, тайм-ауты, HTTP 403 и недостаточный объём не считаются успехом.

Все 22 стратегии проверяются даже при полностью доступном обычном подключении. Кандидаты ранжируются по числу успешных тестов, но не должны терять доступные в исходной серии цели/протоколы. Подходящий кандидат проверяется повторно: каждый ранее успешный адрес, протокол и раунд должен снова пройти. При неудаче проверяется следующий кандидат. Результаты равные обычному подключению показываются честно, без заявления об улучшении. Частичный доступ отделён от полного успеха.

Поиск сам не включает рекомендованную стратегию: после него восстанавливается прежний режим, пользователь нажимает «Включить выбранную». После отмены/ошибки также восстанавливается прежний режим. Если во время проверки запустилась игра, следующие переключения блокируются; статус объясняет, почему текущий маршрут сохранён. Запуск выбранной стратегии проверяется по реально работающему процессу, а не по нажатию кнопки. Произвольные имена стратегий отклоняются основным процессом; допускаются только 22 закреплённых идентификатора.

HTTPS не подтверждает голосовой UDP Discord, QUIC-видеопоток, вход в матч Fortnite или снижение пинга. Даже когда все тесты доступны, можно выбрать другой вариант и проверить голос вручную. Измеренное время HTTPS не называется игровым пингом. Режим внешнего DPI-suite из исходной утилиты, отправляющий POST на загружаемые из интернета узлы, здесь не исполняется.

При сборке из BAT извлекаются только фиксированные аргументы winws. Сохраняются все исходные стратегии и списки; три пользовательских списка создаются с исходными непустыми значениями из service.bat. Проверяется наличие всех списков и фейков, на которые ссылаются стратегии. Меню обновления/удаления чужих служб не исполняется. Широкий игровой фильтр выключен, чтобы не конфликтовать с FortniteFix.

## fnport

Сетевой код взят из официального тега v0.6.3, коммит `855eb018c116c7838a5d0229a1eef3001e6e25dd`. Из него собран отдельный компонент без Gio-окна и трея. Алгоритмы проверки UDP, исходящих портов, TTL, запасных фейков и спасения замёрзших потоков сохранены. WARP выключен и не настраивается; регистрация и ключи не запрашиваются. Поддерживаемые настройки ограничены встроенными фейками и TTL 1–9.

На Windows создаётся собственный временный адаптер `fnport-GTMPC-<PID>` через подписанный Wintun. Как в оригинале, IPv4 трафик к шести диапазонам AWS Europe направляется в этот адаптер; игровой UDP 9000–9999/15000–15999 использует проверенные исходящие порты. TCP и прочий UDP к этим диапазонам проходят через встроенный стек напрямую. Отдельно запущенный fnport может конфликтовать с нашим адаптером; GTM PC не завершает чужие процессы. Выход через виртуальный адаптер больше не запрещается по одной эвристике.

Это не раздельное туннелирование по процессу. Другие приложения, обращающиеся к этим IPv4 диапазонам, тоже используют локальный адаптер. IPv6 через fnport не обрабатывается, DNS Windows не меняется. Когда роутер/CGNAT меняет исходящий порт или применён другой тип ограничения, fnport может не помочь; проверка сохраняет различие между «не отвечает», «заморозка» и обычными потерями. Счётчики соединений — фактические счётчики ядра, а не подтверждение матча или снижения задержки.

## Права и восстановление

Открытие страницы и чтение статуса не требуют администратора и не запускают перехват. UAC появляется при первой сетевой операции для отдельного PowerShell-супервизора. Всё приложение не повышается. Команды имеют фиксированный набор действий и проверяются основным процессом и супервизором; произвольные программы/команды из интерфейса не принимаются.

Каждый дочерний процесс заключён в отдельный Windows Job Object с kill-on-close. Завершаются только собственные процессы, не все `winws`/VPN по имени. Супервизор проверяет PID/время старта GTM PC и heartbeat: при закрытии, ошибке или потере связи останавливает свои компоненты. fnport закрывает временный адаптер вместе с добавленными на него маршрутами; ОС также освобождает его при завершении дочернего процесса. Исходные DNS/маршруты физических адаптеров и реестр сети не переписываются.

WinDivert не захватывается, если его служба принадлежит другой установке. Для своего драйвера очистка проверяет точный путь, отсутствие других известных пользователей драйвера и остановленное состояние; чужие службы не удаляются. После аварии собственный оставшийся драйвер узнаётся по пути пакета. Если Windows или античит блокирует компонент, приложение показывает ошибку; защиту, подписи драйверов и античит не отключает. EAC может остановить WinDivert: для игрового UDP Fortnite предназначен fnport, а не игровой фильтр Zapret.

Отчёт сохраняется пользователем локально через диалог. Отправки на сервер нет. Он содержит версии, результаты публичных проверок и технические счётчики, не авторизационные данные; fnport маскирует IP в диагностических строках.

## Источники и лицензии

`shared/blocking-components.json` закрепляет официальные URL и SHA-256 архивов. Wintun дополнительно сверяется с SHA-256 из официального build.sh fnport. При сборке и запуске проверяется целостность компонентов; Windows CI проверяет подписи Wintun и WinDivert. Пользователю не нужны Go, Python, ручные скачивания или команды.

В поставку входят MIT-лицензии fnport и zapret, лицензии Go-зависимостей, лицензия Wintun, LGPL/GPL WinDivert и лицензии Cygwin. Рядом находятся соответствующие исходники Cygwin 3.4.10, WinDivert 2.2.2 и fnport 0.6.3. Наши адаптации доступны в `native/blocking`, `scripts/prepare-blocking.py`, `electron/blocking-*`. Меню Flowseal, меняющее внешние службы, не поставляется.

## Проверки

Node-тесты проверяют валидацию параметров, HTTPS-ошибки и тайм-ауты, полный перебор даже при доступном исходном соединении, отсутствие ложного улучшения при равенстве, повторное подтверждение каждого адреса/протокола и восстановление при отмене. Тесты исходного Go-ядра проверяют обработку потоков, QoS, отчёты, сетевые утилиты. Chromium проверяет обе темы, видимый поиск, прогресс, выбор/включение результата, отмену, блокировку поиска при FortniteFix, анимированные плашки, общую настройку анимаций и сохранение отчёта на управляемом native bridge.

Добавлен изолированный Windows-тест с двумя настоящими Wintun-адаптерами: нативные сокеты Windows передают TLS-ответ объёмом более 128 КиБ и игровой UDP через производственное ядро; второй адаптер изображает локальную тестовую сеть, а не внешний VPN. UDP проходит через настоящий подбор исходящего порта. Исходная стратегия DiscordFix включена только для частного тестового адреса, её захват TLS подтверждается журналом WinDivert. Сертификат доверен только тестовому клиенту, не устанавливается в Windows. Все адаптеры и маршруты удаляются, тест не поставляется пользователям.

На одноразовом Windows runner также выполняются компиляция рабочего супервизора, проверка подписей, self-test headless-ядра, реальный запуск WinDivert на изолированном неиспользуемом TCP порту, создание/удаление Wintun и остановка при потере heartbeat. Дополнительно все 22 исходные стратегии запускаются и останавливаются с фильтром только на изолированный тестовый адрес. Упаковка сверяется по манифесту хэшей. Эти проверки не подтверждают обход на подключении пользователя и не подтверждают вход в Fortnite. Проверка Creative, обычного матча, голоса и видео требует ПК и подключения пользователя.
