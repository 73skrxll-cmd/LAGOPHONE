# Игровая оптимизация: исследование и границы проверки

Исследованы исходники:

- [hellzerg/optimizer](https://github.com/hellzerg/optimizer/tree/cc88a0e79bde103dd30dcb9fa1f166ac9ad5d924): OptimizeHelper.cs.
- [Microsoft: Multimedia Class Scheduler Service](https://learn.microsoft.com/windows/win32/procthread/multimedia-class-scheduler-service), [исходник документа](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/ProcThread/multimedia-class-scheduler-service.md).

## Выводы для реализации

| Механизм | Когда возможна польза | Что проверяет GTM PC |
| --- | --- | --- |
| Высокий CPU-приоритет | При конкуренции игры с фоновыми процессами за CPU; не гарантирует рост FPS на свободном CPU | Точный путь, PID и время создания текущего процесса; фактический High; правило CpuPriorityClass=3 для имени EXE следующих запусков |
| Производительная GPU для EXE | Если Windows выбирала интегрированную GPU вместо дискретной | Значение GpuPreference=2 для выбранного пути; фактический выбор драйвера зависит от оборудования |
| MMCSS GPU Priority=8 из ряда твикеров | Оснований обещать эффект нет: Microsoft пишет, что этот параметр пока не используется | В игровой профиль не включён |
| SystemResponsiveness=1 | Microsoft указывает, что значения ниже 10 заменяются на 20, то есть это не обещаемый «резерв 1%» | В независимый игровой профиль не включён |

## Подготовка шейдеров удалена

С версии 0.9.0 подключение SCSKiller, вызовы его CLI и подготовка шейдеров исключены из приложения. Игровая кнопка выполняет только настройки CPU/GPU. Обновление не удаляет отдельно установленный SCSKiller и его кеши.

## Независимость и проверка

Игровая кнопка принимает только game-gpu/game-priority и не меняет системные твики или питание. Журнал игровых операций хранится отдельно; обычной кнопки отката в игровом интерфейсе нет. Внутренняя транзакционная копия нужна для восстановления при ошибке и проверяется тестами. Никакого Realtime-приоритета, закрытия посторонних программ или внедрения в игру GTM PC не делает.

В Windows CI тестируется не только запись реестра: отдельная копия cmd.exe под именем cs2.exe получает реальный High, второй запуск проверяет сохранённое правило, контрольная сумма системного журнала остаётся прежней. Это проверка механизма на одноразовом runner, не доказательство прироста FPS в настоящей игре или совместимости с каждым античитом. Для сравнения FPS и фризов на своём ПК нужны одинаковый сценарий, графические настройки, драйвер и лимит FPS, а также замеры времени кадра до и после.

## Обратная связь операции

Частицы начинают движение от фактического положения кнопки к центру логотипа, постепенно меняют белый цвет на золотистый и собираются в ореол и горизонт событий. Логотип расположен на поверхности чёрного центра; при пролёте его частично перекрывает ближняя дуга кольца. Успешный ответ операции запускает ускорение вращения; ошибка или отмена не включают успешное завершение. Уже настроенная игра при открытии показывает сформированный горизонт без повторного запуска оптимизации. Вращается только внешнее кольцо — вокруг вертикальной оси в объёме, с изменением видимого наклона и глубины. Логотип, чёрный центр, круговой горизонт и окружающие его световые точки неподвижны. Дальняя половина кольца скрыта за центром. Ближняя половина рисуется отдельным верхним слоем и проходит перед сферой и логотипом, включая текстовые названия игр и SVG-эмблемы. Область логотипа снова компактна: кольцо не переворачивается целиком в плоскости экрана.

Анимация использует собственный Canvas/rAF-таймер и не зависит от настроек анимации Windows, prefers-reduced-motion и переключателя фоновых эффектов. В скрытом разделе, свёрнутом окне или при потере фокуса таймер приостанавливается. Проценты выполнения не имитируются; текст результата отражает ответ Windows без искусственной задержки ради анимации.

Проверка интерфейса: `npm run test:ui` запускает Vite и Chromium (путь можно задать через `CHROMIUM_BIN`). Тест проверяет реальные пиксели белых и золотистых частиц, координаты кнопки и логотипа, скрытие дальней и видимость ближней части кольца на нескольких углах, неподвижность пикселей кругового горизонта, перекрытие настоящих пикселей текста Fortnite и SVG Dota 2 на композитных снимках браузера, границы объёмного вращения, последовательность стадий, ускорение после ответа, ошибку/отмену, повторный запуск, смену размера окна, скрытие раздела, prefers-reduced-motion и отключение фоновых эффектов. Снимки сохраняются во временный каталог. Этот тест включён в CI перед сборкой Windows.

Для записи цикла движения можно задать `GTM_CAPTURE_ORBIT=<каталог>` перед `npm run test:ui`: после основных проверок сохраняются 96 кадров одного оборота внешнего кольца. В обычном CI запись выключена.
